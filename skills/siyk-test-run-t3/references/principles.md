# Siyrs Skill 第一性原则

本文件适用于 `siyrs-skill` 和所有 `siyk-*` Skill。它们是全局行为约束，不属于某个具体功能点。

## 1. Markdown-first

工程知识默认优先使用 Markdown 表达，包括规则、索引、项目地图、测试用例、测试标准、测试报告、设计/决策说明、计划和交付说明。

- 能用清晰自然语言和链接表达的知识，不为了“更结构化”额外引入 JSON/YAML schema、state、registry、cache 或数据库。
- 目标仓库已有源码、配置或数据格式时继续遵循其原生格式，不把真实代码或原生配置强行改成 Markdown。
- 只有工作本质需要**可执行、确定性、重复自动化或机器校验**时，才新增 script/code；脚本应解决真实重复问题，而不是把自然语言规则机械编码一遍。
- Markdown 也要保持轻量：有真实内容才创建文件或目录，不生成只有 TODO、占位符或仪式性模板的文档。

## 2. 事实优先，不懂不猜

遇到不确定信息时，优先查证而不是补全想象。默认顺序：

1. 先理解用户当前请求和已经提供的上下文；
2. 项目存在 `.siyrs/README.md` 时先用它定位，再读取仓库说明、真实代码、配置、测试和相关 diff；
3. 使用当前可用的工具、命令或权威文档继续核实关键事实；
4. 如果仍然存在会实质影响实现、测试、交付或安全性的关键歧义，直接询问用户，不要瞎猜。

只有在信息缺口属于**低风险、可逆、不会改变核心结果**的小细节，并且继续执行明显比打断用户更合理时，才允许采用最小假设；此时应在结果中明确说明该假设。

禁止编造或臆测以下内容：

- 不存在或未确认的文件路径、模块、命令、API、依赖、配置键、环境变量；
- 权限、账号、凭证、secret、生产环境状态；
- 用户没有表达过的需求、验收规则或业务语义；
- 没有真实执行过的测试结果、构建结果、CI 状态或发布结论。

如果证据相互冲突，优先相信当前真实文件和实际执行结果；无法可靠消解冲突时，把冲突说明给用户并询问。

## 规范来源

每个独立 Agent Skill 都是自包含包：

- 当前 Skill 的 `references/*.md` 是共享规则的**权威运行时规范来源**；
- 当前 Skill 的 `SKILL.md` 是**行为入口**：说明何时执行、需要读取哪些规范、本 Skill 的独特职责和停止边界；
- Skill 执行不得依赖 Skill 根目录之外的文件；不依赖 Collection 仓库的 README、docs、父目录或其他 Skill；
- 同一规则在源码层只维护于 `shared/references/`，由确定性同步工具物化到需要它的 Skill 包，避免人工复制和规则漂移。

修改共享规则时先修改 Collection 中对应的 `shared/references/*.md`，再运行同步与校验；不要直接把多个运行时副本改成不同版本。

## 两条原则如何配合

- **Markdown-first** 决定知识优先用什么形式沉淀。
- **事实优先，不懂不猜** 决定这些知识必须基于什么证据产生。

目标不是减少思考，而是减少不必要的机器结构和未经验证的推断。
